# Step: Implement

## Before you start

- Read grounding docs and understand existing code before changing it
- Ask when blocked; do not pick an interpretation silently
- Keep changes reviewable; prefer small diffs

## During

- Follow the stack, language, and tool modules enabled for this project
- Act as the developer agent for this step
- Propose new portable practices as rule candidates; wait for approval before adding library rules

## Before you finish this step

- Hand off to Review; do not claim Verify done yet
